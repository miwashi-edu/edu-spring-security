# REQ-030: Cookie-authenticated requests should require a CSRF token

> Refresh and logout (authenticated by cookie) require the CSRF token: `XSRF-TOKEN` cookie repeated in the `X-XSRF-TOKEN` header.

## Test case

| | |
|---|---|
| **Id** | REQ-030 |
| **Tag** | `@Tag("REQ-030")` |
| **Suggested test** | Black-box · Security |
| **Suite** | Security |
| **Runs in** | `dev`, `stage` |
| **Precondition** | Server is running with the test accounts (`user`, `admin`, `superadmin`, password `TEST_PASSWORD`) |
| **Action** | GET `/api/csrf`; refresh/logout without token, with a mismatching token, with header only, and with a correct token |

**Expected result**

1. `/api/csrf`: `200` and a `XSRF-TOKEN` cookie that is not `HttpOnly`
2. Missing or wrong token: `403`
3. Correct token: `200`

Changed from the earlier example: refresh is now `POST /api/auth/refresh` instead of `GET /api/refresh`, since a cookie-authenticated GET cannot be CSRF protected.
