# REQ-021: Access token should be a signed JWT identifying user and roles

> The access token is a signed JWT whose subject is the user's email and whose `roles` claim holds the user's role.

## Test case

| | |
|---|---|
| **Id** | REQ-021 |
| **Tag** | `@Tag("REQ-021")` |
| **Suggested test** | White-box · Unit, Black-box · Security |
| **Suite** | Security |
| **Runs in** | `dev`, `stage` |
| **Precondition** | Server is running with the test accounts (`user`, `admin`, `superadmin`, password `TEST_PASSWORD`) |
| **Action** | Log in as each test account and decode the access token |

**Expected result**

1. Three parts, `alg` is `RS256`, `ES256`, `EdDSA` or `HS256` (never `none`)
2. `sub` = email
3. `roles` contains `USER`, `ADMIN` or `SUPERADMIN`
