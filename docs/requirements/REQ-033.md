# REQ-033: Password changes should follow the password policy

> `POST /api/auth/password` requires authentication and the current password, and enforces length 12–128, no common passwords, not containing the email, different from the current one (NIST SP 800-63B).

## Test case

| | |
|---|---|
| **Id** | REQ-033 |
| **Tag** | `@Tag("REQ-033")` |
| **Suggested test** | White-box · Unit, Black-box · Integration |
| **Suite** | Security |
| **Runs in** | `dev`, `stage` |
| **Precondition** | Server is running with the test accounts (`user`, `admin`, `superadmin`, password `TEST_PASSWORD`) |
| **Action** | Change the user's password to rejected values |

**Expected result**

1. Too short / too long / common / contains email / unchanged: `400`
2. Wrong current password: `403`
3. Not logged in: `401`

Only rejected changes are tested, so the account password never changes. The default `TEST_PASSWORD` was changed from `password` to `Correct-Horse-Battery-42` because the old one violates this policy.
