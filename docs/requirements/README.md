# Requirements

Every requirement has an id `REQ-nnn` and its own file. Tests are named as spoken requirements
(`HealthEndpointTest.shouldReportUP` reads "Health endpoint should report UP") and carry the ids
they verify as `@Tag("REQ-nnn")`, so every requirement can be traced to the tests that cover it.

**Students:** start with [TEST-MATRIX.md](TEST-MATRIX.md), all requirements as one-liners with an
empty *Tested in* column to fill in, then compare with the generated matrix below.

## Test suites

| Suite | Type | Source folder | Run with |
|---|---|---|---|
| Unit | White-box: starts the application in-process | `app/src/test/unit/java` | `gradle :app:test` |
| Smoke | Black-box: quick HTTP checks against a running server | `app/src/test/smoke/java` | `gradle :app:smokeTest` |
| Security | Black-box: authentication, tokens, CSRF, roles, attacks | `app/src/test/security/java` | `gradle :app:securityTest` |

All tests are in package `org.example.test`. Settings (backend URL, profile, accounts, endpoints)
are environment variables, see `org.example.test.Constants`. Against another server:

```shell
TEST_BACKEND_URL=https://stage.example.com TEST_PROFILE=stage gradle :app:smokeTest :app:securityTest
```

## Security API (contract the tests define)

| Endpoint | Purpose | Auth |
|---|---|---|
| `POST /api/auth` `{email, password}` | Login → `{"object": accessToken}` + `refreshToken` cookie | – |
| `POST /api/auth/certificate` `{assertion}` | Certificate login (signed JWT) → as login | – |
| `POST /api/auth/refresh` | New access token, rotated refresh cookie | refresh cookie + CSRF |
| `POST /api/auth/logout` | Revoke refresh token, clear cookie | refresh cookie + CSRF |
| `POST /api/auth/password` `{currentPassword, newPassword}` | Change password | Bearer |
| `GET /api/csrf` | `XSRF-TOKEN` cookie (repeat in `X-XSRF-TOKEN` header) | – |
| `GET /api/me` | `{email, roles}` | Bearer |
| `GET /api/user`, `/api/admin`, `/api/superadmin` | Role areas | Bearer + role |
